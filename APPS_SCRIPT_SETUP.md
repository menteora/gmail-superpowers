# Gmail Superpowers - Apps Script prototype

This is the first Google Workspace Add-on prototype. The existing Gmail userscript keeps using IndexedDB locally. The add-on uses a Google Sheet as its own database. `gmail-superpowers-sync.user.js` is the bridge between the two stores.

## Architecture

```text
Gmail Superpowers userscript
        |
        | IndexedDB
        v
Sync Bridge (Tampermonkey)
        |
        | HTTPS POST + private token
        v
Apps Script Web App
        |
        v
Google Sheet: Gmail Superpowers DB
        ^
        |
Google Workspace Add-on sidebar
```

The bridge does not expose IndexedDB directly to Apps Script. It serializes the four existing stores (`thread-notes`, `deadlines`, `cases`, `case-members`) and merges them into the Sheet. Records use timestamps so the newer copy wins.

## Files

```text
apps-script/Code.gs                 Apps Script add-on + Web App endpoint
apps-script/appsscript.json         Workspace Add-on manifest
gmail-superpowers-sync.user.js     Tampermonkey bridge
.clasp.json.example                clasp project template
.claspignore                       only pushes Apps Script sources
```

The main `gmail-superpowers.user.js` is deliberately outside `apps-script/` and is also excluded by the clasp configuration. It is never pushed to Apps Script.

## 1. Create the Apps Script project

Install clasp if needed:

```bash
npm install -g @google/clasp
clasp login
```

Create a standalone Apps Script project in the Apps Script UI or with clasp. Copy its Script ID, then from the repository root:

```bash
cp .clasp.json.example .clasp.json
```

Put the Script ID in `.clasp.json`:

```json
{
  "scriptId": "YOUR_SCRIPT_ID",
  "rootDir": "apps-script"
}
```

Then push:

```bash
clasp push
```

`.claspignore` lives next to `.clasp.json`, while its patterns are evaluated relative to `rootDir=apps-script`. Therefore the Tampermonkey scripts at repository root cannot be uploaded by `clasp push`.

## 2. Initialize the Sheet database

In the Apps Script editor run once:

```text
setupGmailSuperpowers
```

Authorize the requested Gmail and Sheets scopes.

The function creates a spreadsheet named:

```text
Gmail Superpowers DB
```

and a `records` sheet with one row per logical record. It also creates a private bridge token in Script Properties.

## 3. Deploy the Workspace Add-on for testing

Create a test deployment of the Workspace Add-on and install it on your account. In Gmail the right sidebar will expose Gmail Superpowers.

When a message is opened, the contextual card can edit:

- conversation status;
- deadline;
- Case membership;
- Case status;
- creation of a new Case.

If a Case is linked, the card also lists its related conversations with latest known email time, deadline and conversation status.

## 4. Deploy the same project as a Web App

The sync bridge uses `doPost`, so create a second deployment of the same Apps Script project as a Web App.

For this personal prototype use:

```text
Execute as: Me
Who has access: Anyone
```

The endpoint is protected separately by the long random token generated by `setupGmailSuperpowers`. Keep that token private. If it leaks, use the add-on home action **Rigenera token bridge** or run `rotateSyncToken()`.

Copy the `/exec` Web App URL.

## 5. Install the Tampermonkey bridge

Install:

```text
https://raw.githubusercontent.com/menteora/gmail-superpowers/main/gmail-superpowers-sync.user.js
```

In Tampermonkey's menu for the bridge choose:

```text
GSP Sync: configura Apps Script
```

Enter:

1. the Apps Script Web App `/exec` URL;
2. the private bridge token shown in the add-on home card or returned by `setupGmailSuperpowers()`.

Then choose **GSP Sync: sincronizza ora** for the first migration from IndexedDB to the Sheet.

## Data model in the Sheet

All record types share a single table. `type` determines the logical entity:

```text
note       per-conversation status
deadline   per-conversation due date
case       Case name and Case status
member     conversation-to-Case link + latest email metadata
```

For conversations the Sheet normalizes keys to `thread:<gmail-thread-id>` when a thread ID is available. This avoids depending on Gmail's local `/u/0`, `/u/1`, etc. slot when exchanging data between Tampermonkey and the add-on.

## Prototype limitation

The first bridge is intentionally kept separate from the main userscript so the current Gmail UI remains stable while the add-on is tested. Once the data model and synchronization are proven, the bridge can be folded into `gmail-superpowers.user.js` and the second Tampermonkey installation removed.
